# ABCNote Qt 设计规格

日期：2026-05-02

## 目标

构建 ABCNote，一款面向电脑端和手机端的跨平台 Qt 6 随身笔记应用。第一版目标是完成一个可运行的 Qt C++/QML 工程：启动后自动打开今天的笔记，右侧以连续日期流的形式显示笔记内容，并把笔记按年/月/日结构保存到本地文件。

## 平台与构建

ABCNote 使用 Qt 6、CMake、C++17 和 QML。

如果需要安装 Qt 相关工具或 SDK，安装目录应放在 `D:\Program\dev` 下。项目源码目录保持在 `E:\work\ABCNote`。

构建系统使用 CMake，方便同一个工程被 Qt Creator 打开，也能从命令行构建，并为后续适配 Android 或 iOS 留出空间。

本项目工作过程中生成的文档应同时提供英文版和中文版。

## 用户体验

主窗口采用通用笔记软件布局：

- 顶部工具栏显示应用名称和简单操作。
- 左侧导航栏按日期展示笔记。
- 右侧内容区以类似纸张的可编辑页面展示每日笔记，并支持连续滚动。

左侧导航严格保持三层逻辑结构：

- 年，例如 `2026`。
- 月，例如 `05`。
- 日文件，例如 `2026-05-02`。

应用启动时，如果今天的笔记不存在，就自动创建；随后加载今天附近的一段日期，并把右侧内容区定位到今天的笔记。

右侧内容区使用垂直 QML 列表。当用户接近顶部时加载更早日期；当用户接近底部时加载更晚日期。这样可以形成近似无限的时间线滚动体验，同时只让界面保留有限数量的可见委托项。

每一天的笔记包含：

- 标题：日期。
- 主体：可编辑的笔记正文。
- 总结：自动生成的简短总结。

## 数据模型

第一版把每篇日记保存为一个 JSON 文件：

```text
data/
  2026/
    05/
      2026-05-02.json
```

每个文件内容如下：

```json
{
  "date": "2026-05-02",
  "contentBody": "",
  "aiSummary": "",
  "updatedAt": "2026-05-02T12:00:00"
}
```

这种结构符合年/月/日三级日期文件要求，也便于以后备份、查看和同步。

## C++ 组件

`Note` 是单个日期笔记的内部数据对象。

`NoteStorage` 负责读取、写入、创建目录，以及尽量使用原子替换方式保存文件。

`NoteModel` 是暴露给 QML 的 `QAbstractListModel`，用于右侧连续笔记流。它提供日期、格式化日期文本、正文和总结等角色，并支持加载前后日期范围。

`NavigationModel` 是暴露给 QML 的 `QAbstractListModel`，用于左侧日期导航。它用行数据表示年、月、日，并提供层级信息给 QML 做缩进。

`NoteController` 暴露给 QML，用于处理更新笔记正文、保存待写入内容、跳转到日期、重新生成总结等用户操作。

## 自动保存

QML 中的文本变化通过 `NoteController` 发送到 C++。

控制器会把对应笔记标记为已修改，并启动一个短延迟保存定时器，约 800 毫秒。连续输入会重置定时器，避免每个按键都写入磁盘。

定时器触发后，所有待保存笔记通过 `NoteStorage` 写入文件。

应用还会在以下情况强制保存待写入内容：

- 正常退出应用。
- 关闭窗口。
- Qt 支持的应用状态变化。
- 后续添加的显式保存操作。

写入时先写临时文件，再替换或重命名为目标文件。这样可以降低应用或系统中断时损坏原有笔记文件的风险。

突然断电无法由应用代码完全保证零丢失，但频繁的延迟保存和原子替换可以尽量减少损失。

## AI 总结

第一版先实现本地占位总结生成器，这样不需要网络凭据也能完成 UI 和数据流。

本地总结会从正文中提取简短摘要，例如提取前几句有意义的文字，或生成一个截断后的预览。

C++ 边界应把总结逻辑隔离在 `SummaryService` 后面。后续如果接入 OpenAI、本地模型或自定义 API，可以替换该服务，而不需要改动 QML。

## QML 集成

现有文件将作为视觉和布局起点继续使用：

- `Layout/Main.qml`
- `Layout/NoteItemDelegate.qml`

QML 会清理为 UTF-8 中文文本，使用 Qt 6 import，修正模型角色名，并提升编辑器行为的可靠性。

`Main.qml` 负责应用主布局，并调用控制器完成导航和无限加载。

`NoteItemDelegate.qml` 渲染单个日期笔记页面，并在正文变化时通知控制器。

## 错误处理

如果某个笔记文件无法解析，应用不应立刻覆盖它。可以在内存中加载一个空笔记，并向调试输出写入警告。

如果保存失败，控制器应保留该笔记的待保存状态，并向 UI 暴露状态消息。

如果数据目录不存在，应用会自动创建。

## 测试与验证

第一版应验证：

- CMake 可以配置并构建。
- 应用可以启动并加载 QML。
- 启动时会创建今天的笔记文件。
- 编辑笔记正文后会创建或更新 JSON 文件。
- 可以加载前一天和后一天的笔记。
- 左侧导航行符合年/月/日结构。

自动化测试可以优先覆盖 `NoteStorage`、日期范围加载和总结生成，因为这些逻辑独立于 QML 界面。
